This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

The website for Siloé, a French church worship choir ("Choeur d'Adoration"). It's a [Docusaurus](https://docusaurus.io/) 3 site whose primary content is French-language markdown: song lyrics, service (culte) programmes, a life-of-the-choir section, and a blog ("Journal"). There is very little application code — most work in this repo is authoring/editing markdown docs, not writing JS.

## Commands

```bash
npm start           # local dev server with live reload
npm run build        # build static site into build/
npm run serve         # serve the built site locally
npm run clear          # clear Docusaurus cache
npm run deploy          # build and push to gh-pages (USE_SSH=true or GIT_USER=<user> env var required)
npm run write-heading-ids  # generate explicit heading ids in docs
```

There is no test suite and no linter configured in this repo. `npm run build` (with `onBrokenLinks: 'throw'` in `docusaurus.config.js`) is the main correctness check — it fails the build on any broken internal link, so always run it after adding/renaming/moving docs.

Deployment is automatic: `.github/workflows/deploy.yml` builds with `npm ci && npm run build` and publishes `build/` to GitHub Pages on every push to `main`. There is no separate CI/PR check — pushing to `main` deploys straight to production.

## Content architecture

Content lives in three doc collections plus the blog, each with its own sidebar defined in `sidebars.js` and rendered via the single `docs` preset in `docusaurus.config.js`:

- **`docs/chants/`** — song lyrics repertoire. `repertoire.md` is the pinned landing page (`sidebar_position: 1`); everything else in the directory is autogenerated into the sidebar from frontmatter (`title`, `sidebar_label`).
- **`docs/programmes/`** — service/event programmes (song lists per culte). `liste-programmes.md` is the pinned landing page. Dated programme files follow the naming convention **`AAAA-MM-JJ-description.md`** (e.g. `2026-08-02-culte.md`) — this date prefix is load-bearing, not just a convention: `src/plugins/latest-programme.js` scans this directory, parses filenames against `/^(\d{4}-\d{2}-\d{2})-(.+)\.md$/`, and sets `latestProgrammeSlug` as global plugin data. The homepage (`src/pages/index.js`) reads that value via `usePluginData('latest-programme')` to link its "Programme" button to the most recent culte. Non-conforming filenames are silently excluded from that lookup.
- **`docs/vie-de-la-chorale/`** — static choir-life pages (charte, règlement), fully autogenerated sidebar, no pinned landing doc.
- **`docs/tutoriels/`** — in-site tutorials, autogenerated sidebar. Note there is a separate, unpublished **`tuto/`** directory at the repo root with source tutorial content (`ajouter-un-chant.md`, `ajouter-un-programme.md`, `publier-un-article.md`) — these are the authoritative step-by-step guides for the three common authoring tasks below and should be kept in sync with reality if the corresponding content conventions change.
- **`blog/`** — the "Journal", using the standard Docusaurus blog plugin (title/description overridden in `docusaurus.config.js`). Post filenames start with a date (`AAAA-MM-JJ-titre.md`). Use `<!--truncate-->` to control the list-view excerpt.

### Adding content — conventions to follow (from `tuto/`)

- **New song**: `docs/chants/<slug-no-accents-hyphenated>.md`, frontmatter `title` + `sidebar_label`, body with `**Auteur :**` / `**Tonalité :**` and lyrics under `>` blockquotes per section (Couplet, Refrain, ...).
- **New programme**: `docs/programmes/AAAA-MM-JJ-description.md` (date prefix required for the "latest programme" homepage link to pick it up), frontmatter `title` + `sidebar_label` (+ `sidebar_position` to control ordering, see existing files), body with `**Type :**` / `**Lieu :**` / `**Heure :**` and a markdown table of chants per section (Entrée, Adoration, Louange, Offrandes, Clôture, etc.). Link song rows to their lyrics page with `[Nom du chant](/docs/chants/nom-du-fichier)` where available.
- **New blog post**: `blog/AAAA-MM-JJ-titre.md`, frontmatter `title`, `authors` (see `blog/authors.yml`), `tags` (conventional set: `répétition`, `événement`, `vidéo`, `annonce`). For embedding YouTube videos, import and use the custom `<YouTube videoId="..." title="..." />` component (`src/components/YouTube/`) — supports multiple embeds per post.

## Site-level notes

- Locale is `fr` only (`i18n.defaultLocale: 'fr'`), no i18n routing to worry about.
- `colorMode` is pinned to dark with the switcher disabled (`disableSwitch: true`) — don't add UI assuming a light theme is reachable.
- `baseUrl` is `/groupe_siloe.github.io/` and `organizationName`/`projectName` are set for GitHub Pages under the `fabriceHategekimana` account — these must stay consistent with the deploy workflow and repo's GitHub Pages settings.
- The `build/` and `.docusaurus/` directories are generated output, not source — don't hand-edit them.
